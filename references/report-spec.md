# 诊断报告规范（HTML 评分卡 + 病因库 + 输出模板）

## 一、HTML 报告骨架（固定 9 区块，不增不减）

单文件 HTML，零外部依赖（图表用内联 SVG + CSS，不引 CDN，保证离线可开）。

| 区块 | 内容 | 视觉要求 |
|---|---|---|
| 1 报告头 | 平台、账号名、诊断日期、数据截止日、可信度等级 | 横版页眉，红金分隔线 |
| 2 一句话结论 | 只写**一个**主要矛盾，一句话说完；下附一条反例证据 | 超大字，占首屏视觉重心 |
| 3 评分总表 | 6 模块得分 / 满分 / 得分率 + 总分与等级；**表下必须附六模块释义卡**（每模块三行：测什么 / 为什么占这个分值 / 最容易犯的错） | 表格 + 横向分值条 + 3 列×2 行释义卡 |
| 4 雷达图 | 6 维雷达，本次 vs 上次（有历史时叠两条）；标注"中心=0，外圈=100%" | 内联 SVG，红金双色 |
| 5 漏斗现状 | 曝光/播放 → 点击/完播 → 互动 → 关注 → 咨询，标出断点；附"怎么看这张图"三行说明 | CSS 漏斗条，断点用红色标注 |
| 6 问题清单 | ≤5 条，按"影响面 × 修复成本"排序 | 每条一张卡：证据→病因→改法→判据 四段**分层展开**（见第二节） |
| 7 不建议做什么 | 明确排除的无效动作，每条必须带理由 | 小字，放在末页 |
| 8 本报告可能错在哪 | 预设失败判据：列出 3–4 条"什么情况说明这份报告判断错了" | 小字，紧跟区块 7 |
| 9 可信度声明 | 哪些有数据支撑、哪些是〔经验〕推断、缺测几项、未下结论的部分 | 小字灰底，末页收口 |

打印：A4 横版（297×210mm），`@media print` 去动画、保底色。
配色：主色 `#C41230`，辅色 `#CAAA74`，正文深灰 `#2B2B2B`，底色 `#FAF8F5`。
字体：`PingFang SC, 思源黑体, Microsoft YaHei`，标题 32–48px，正文 14–16px。

**区块 3 的释义卡为什么必须有**：六个模块名（账号层 / 内容层 / 结构层 / 数据层 / 转化层 / 差异化）对非从业者不构成信息，只写"71%"等于让人自己猜。释义卡要回答三个问题，每个都不许写空话：

- **测什么** —— 列出这个模块下具体的评分项，不写"综合评估"这种词。
- **为什么占这个分值** —— 平台机制层面的理由，不写"这个很重要"。
- **最容易犯的错** —— 一条具体的、这个平台的典型误用。

## 二、问题卡固定格式（四段分层展开）

每张卡四段，每段内部再分小项。**不许把四段压成四句话**——那是摘要，不是诊断。

```
【问题 N】<一句话标题，说清"哪一步做错、导致什么结果">
优先级 N / 5 · <影响面一句话>

┌ 证据 〔来源标签〕
│  位置：第几条、第几秒、哪个页面
│  原文照抄：逐字抄截图里的文字，最多 3 条，不概括、不改写
│  画面：描述截图能看到的视觉事实
│  为什么算问题：这条违反了哪条判定标准，平台机制上会怎么惩罚
│  对照（有就写）：账号内部有没有反例，哪条做对了
└

┌ 病因
│  评分项：M_ 第 N 项「项名」实得分 / 满分
│  扣分依据：把该项的分档口径写出来，说明为什么落这一档，为什么不是上一档
│  连带影响：这个扣分把哪个数据指标拖下来了（指向具体数字）
└

┌ 改法
│  分步：1 / 2 / 3 / 4（每一步都能直接执行，不出现"优化""提升"这类动词）
│  前后对照：至少给一组 ✗ 现在的做法 / ✓ 改成什么，用真实文案举例
│  难度与范围：低/中/高；已发内容能不能改，还是只对下一条生效
└

┌ 判据
│  看哪个数：具体到后台哪个页面、哪个指标名
│  什么时候看：第几天、取几条的中位数（24 小时数据不作判断）
│  算改对：给出目标值或提升幅度
│  没达标：分 2–3 种情况给不同走法（涨了这个没涨那个怎么办、全没涨怎么办）
└
```

**判据是硬要求**：没有判据的改法不许写进报告（对应六步框架第 ⑥ 步"预设失败判据"）。判据里必须有"没达标怎么办"，只有目标值不算判据。


## 三、病因库（按模块）

### M1 账号层

| 症状 | 病因 | 改法方向 |
|---|---|---|
| 搜不到 | 昵称/简介无品类词 | 昵称加"地域+品类"；简介首句带核心词 |
| 点进来就走 | 头像非真人、简介只有情绪词 | 换工作照；简介写清"在哪、拍什么、怎么约" |
| 看不出主营 | 九宫格三类内容混排 | 统一封面字体+角标，按类分组 |
| 不敢约 | 无客片实证、无价格区间 | 客片条前置；写清档期与价格区间（不写联系方式） |

### M2 内容层

| 症状 | 病因 | 改法方向 |
|---|---|---|
| 曝光有、点击低 | 封面信息过载或文字压底 | 砍到 ≤3 行；主体上移，留 15–20% 安全区 |
| 点击有、互动低 | 内容无共鸣或结尾无提问 | 换"具体可答"提问；给可转发实体物 |
| 看完不关注 | 无关注理由 | 加固定栏目名+期数+下期预告 |
| 前 3 秒流失（抖音） | 片头/自我介绍占位 | 直接把结果或冲突放第 1 帧 |

### M3 结构层

| 症状 | 病因 | 改法方向 |
|---|---|---|
| 数据忽高忽低 | 选题随机、无栏目 | 定四支柱比例，按周排期 |
| 断更后掉量 | 节奏中断 | 恢复固定周更，先补 3 条存量 |
| 同类内容越来越差 | 同机位同角度重复 | 换角度/换时段/换主体 |

### M4 数据层

| 症状 | 病因 | 改法方向 |
|---|---|---|
| 曝光低 | 账号权重或赛道容量 | 先看是否合规受罚；再看选题是否偏离搜索词 |
| 点击低 | 封面标题 | 只改封面+标题，7 天后看点击率 |
| 互动低 | 内容没共鸣 | 换开头与提问，不改选题 |
| 关注低 | 无关注理由 | 加栏目化与预告 |

### M5 转化层

| 症状 | 病因 | 改法方向 |
|---|---|---|
| 流量不落地 | 简介没给下一步 | 写清"收藏/关注/看置顶"的站内动作 |
| 评论冷清 | 回复慢、无置顶 | 60 分钟内回；置顶一条关键词回复 |
| 有人问但接不住 | 私信无人管 | 设固定时段集中回复（被动响应，不主动索要联系方式） |

### M6 差异化

| 症状 | 病因 | 改法方向 |
|---|---|---|
| 换个号也一样 | 差异点是"专业/用心" | 换成可感知差异：路线可执行、当天交片、客片即内容 |

## 四、输出六段模板（对话内速览版，HTML 报告之外的摘要）

```
一句话结论：这个号最大的一个问题是 ___（只写一个）。

评分：总分 __/100，等级 __。模块得分率：M1 __% / M2 __% / M3 __% / M4 __% / M5 __% / M6 __%。

漏斗现状：曝光 __ → 点击 __ → 互动 __ → 关注 __ → 咨询 __；断点在 ___（无数据则写"无数据，跳过"）。

问题清单（≤5 条，只动主要矛盾模块）：
1. 【证据】… 【病因】… 【改法】… 【判据】…
2. …

不建议做什么：__（如"先别投流""先别改定位""这次别动封面"）。

可信度声明：___ 项有数据支撑；___ 项为〔经验〕推断；缺测 ___ 项。
```

## 五、硬边界（写报告时逐条自查）

1. **不推断"被限流"** —— 没有后台通知或数据断崖证据，只写"存在限流风险指标"。
2. **不编数据** —— 截图里没有的数字不补、不估、不"合理推测"；缺测就写缺测。
3. **不套模板给建议** —— 每条改法必须指向这个号的具体截图位置；"多发优质内容""提高互动率"这类话一律不写。
4. **不给确定性结论** —— 说"很可能"时给出证据量；只有一项证据时明说证据不足。
5. **跨平台分数不互比** —— 小红书与抖音是两套表，分数只在同平台内纵向比较。
6. **只改主要矛盾** —— 报告里可以记录其他模块的问题，但不给改法，避免"一次改五处、最后不知道哪个起效"。
7. **释义卡不许省** —— 六个模块必须各有三行释义。用户看不懂模块名，后面的分数和改法都白给。
8. **缺测不许折算成"看上去及格"** —— 只算可测部分，表里标"仅测 N 项"，总分用 `实得分 × 100 ÷ 可测满分合计` 折算并**不判等级**，写"暂不判级（缺测 N 分）"。缺测 ≥ 30 分时，一句话结论只下证据最扎实那个模块的结论。
9. **主要矛盾不许机械套公式** —— 某模块**实测覆盖不足其满分的 70%** 时，其得分率不参与"最低"比较（覆盖不足时无法区分"真低"和"缺测"）。全部模块都不达 70% 时，取覆盖最高者并标注"仅参考、不作结论"，同时在"本报告可能错在哪"写死改判条件。

## 六、模块释义卡文案库

写报告时直接取用，可改写措辞但**三行结构不能少**（测什么 / 为什么这个分值 / 最容易犯的错）。

### 抖音（M1 14 / M2 32 / M3 14 / M4 28 / M5 10 / M6 6）

| 模块 | 测什么 | 为什么这个分值 | 最容易犯的错 |
|---|---|---|---|
| M1 账号层 14 | 头像、昵称、简介、主页九宫格，决定"点进主页 3 秒内会不会关注" | 抖音靠推荐分发，多数人刷完就走、根本不点主页；这四项影响**关注率**，不影响播放量 | 把小红书那套搬过来——简介写一大段自我介绍，抖音主页上没人读 |
| M2 内容层 32 | 前 3 秒钩子、首帧与标题、价值类型、关键词、结尾动作、实体物、完播结构 | 推荐池按"看完了吗"分层；内容留不住人，后面所有数据都是零 | 把"我拍了什么"当内容，而不是"观众能得到什么" |
| M3 结构层 14 | 选题分布、更新节奏、发布时段、栏目化与同质化 | 决定的是长期，不是单条；不会让你这条爆，但会让你一直起不来 | 一周内发三种完全不同的题材，观众记不住你是做什么的 |
| M4 数据层 28 | 播放、完播率、互动率、涨粉率；用数据**检验** M2 的判断 | 唯一能推翻主观判断的部分；说"前 3 秒有问题"必须靠留存曲线验证 | 拿绝对值判断好坏（播放 1 万算好吗），应跟自己前 10 条中位数比 |
| M5 转化层 10 | 主页承接、评论承接、咨询链路 | 站内转化路径短且禁止站外引流，能动的位置只有主页和评论区 | 视频里喊"私信我"——抖音同样禁止诱导私信留联系方式 |
| M6 差异化 6 | 差异点、同质度 | 长期加分项，不是短期生死线；缺了会一直停留在"看过的第 37 个拍天坛的人" | 把"我很用心"当差异点——那是自我评价，不是差异 |

### 小红书（M1 16 / M2 30 / M3 14 / M4 22 / M5 12 / M6 6）

| 模块 | 测什么 | 为什么这个分值 | 最容易犯的错 |
|---|---|---|---|
| M1 账号层 16 | 昵称、头像、简介四要素、九宫格统一度 | 小红书用户会主动点进主页（搜索进入占比高），主页是第二次点击的主战场，权重高于抖音 | 九宫格风格不统一，看不出这是个摄影号 |
| M2 内容层 30 | 标题前 8 字、封面可读、开头钩子、价值类型、关键词三层、结尾动作、实体物 | 生死线是信息流里那一眼——封面和标题决定点击率，点击不上来后面什么都没有 | 封面文字压在底部，被信息流标题盖住，等于白做 |
| M3 结构层 14 | 选题分布、更新节奏、发布时段、栏目化与同质化 | 小红书吃长期搜索，栏目化和关键词占位决定第 30 条之后能不能起来 | 每条都在追热点，没有可累积的搜索位 |
| M4 数据层 22 | 曝光、点击率、互动率、涨粉率 | 唯一能证伪主观判断的部分；"封面有问题"必须靠点击率验证 | 只看点赞数，不看点击率——点赞数受推荐量影响，点击率才是封面好坏的尺子 |
| M5 转化层 12 | 主页承接、评论承接、咨询链路 | 不能站外引流，站内链路只有收藏 + 评论置顶 + 被动私信 | 简介写"私信我"，直接踩导流红线 |
| M6 差异化 6 | 差异点、同质度 | 长期加分项；小红书同类摄影号极多，无差异点等于可替代 | 把"我拍得好看"当差异点——好看是入场券，不是差异 |
